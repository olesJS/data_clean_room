# Еталон і словники для PII-детектора

Вхідні дані для PII-детектора (SCRUM-44) і для підрахунку recall та precision. Усі дані вигадані: контрольні суми ІПН, IBAN і карток коректні, але збіги з реальними значеннями випадкові.

## Склад

| Файл | Призначення |
| --- | --- |
| `ground_truth.csv` | **Еталон.** Розмітка кожної колонки чотирьох наборів: `expected_class` (`pii` / `quasi` / `none`), `pii_type`, `trap` (`yes` для пасток), `note` |
| `benchmark_people.csv` | 80 рядків, 12 PII-колонок різних типів (ПІБ частинами, ІПН, паспорт, IBAN, картка, email, телефон п'яти форматів, адреса). 5% значень порожні, ~10% прізвищ і ~8% імен поза словником |
| `traps.csv` | 80 рядків, 12 колонок, **жодна не PII**, але 8 з них навмисно схожі (див. нижче) |
| `dictionaries/` | Словники для детектора: імена чоловічі й жіночі, прізвища, слова адрес, області |
| `../payroll.csv`, `../customers.json` | Основні набори кейсів 1 і 2, розмічені в тому самому `ground_truth.csv` |

Загалом у еталоні 43 колонки: **18 PII**, 25 не PII (з них 8 пасток), 2 квазіідентифікатори (`birth_date`).

## Типи PII (`pii_type`)

`person_name`, `ipn`, `passport`, `iban`, `card`, `email`, `phone`, `address`. Для квазіідентифікатора `birth_date`. Детектор повертає один із цих типів для кожної виявленої колонки.

## Пастки

| Колонка в `traps.csv` | Чим схожа | Чому не PII |
| --- | --- | --- |
| `order_number`, `invoice_no` | 10 цифр, як ІПН | Контрольна цифра ІПН не збігається |
| `transaction_id` | 16 цифр, як картка | Не проходить алгоритм Луна |
| `contract_ref` | `UA` + 27 цифр, як IBAN | Не проходить перевірку mod 97 |
| `part_number` | 9 цифр, як ID-картка | Номер деталі |
| `brand_name` | Слова зі словника імен (Марічка, Дарина) | Назви брендів |
| `product_line` | Слова зі словника прізвищ (Мороз, Жук, Козак) | Назви лінійок продукції |
| `city_name` | Олександрія, Костянтинівка, Миколаїв | Назви міст, схожі на імена |

Це перевіряє, що детектор не ухвалює рішення лише за регулярним виразом або словником, а використовує контрольні суми й частку збігів у колонці. Колонка `city` у `customers.json` також не PII.

## Як порахувати recall і precision

1. Детектор віддає CSV з колонками `dataset,column,pii_type` для **колонок, які він вважає PII** (назви наборів: `payroll.csv`, `customers.json`, `benchmark_people.csv`, `traps.csv`).
2. Запуск: `python scripts/evaluate_pii.py predictions.csv`. Скрипт друкує recall, precision, точність типу та списки пропущених колонок і хибних спрацювань. Код виходу 1, якщо recall нижчий за 90%.
3. Перевірка самого скрипта: `python scripts/evaluate_pii.py --self-test`.

Правила підрахунку: TP, FN і FP рахуються на рівні колонок. Колонки з `expected_class=quasi` не враховуються ні як TP, ні як FP. Тип PII перевіряється окремою метрикою.

**Цільові значення (критерій SCRUM-44):** recall не нижче 90%, мінімум хибних спрацювань. На 18 колонках це означає пропустити не більше однієї.

## Словники

Файли в `dictionaries/` текстові, по одному слову в рядку, рядки з `#` ігноруються. Імена й прізвища подано в називному відмінку; детектор має порівнювати без урахування регістру. Прізвища чоловічої форми: жіночу форму для `-ський/-ий` (`-ська/-а`) детектор повинен обробляти сам. Словники не вичерпні: у benchmark навмисно є імена поза словником, щоб детектор не покладався тільки на них.

## Як перегенерувати

```
python scripts/generate_pii_reference.py   # перезаписує benchmark, traps і ground_truth, потім перевіряє їх
```

Скрипт детермінований (seed 20261031), використовує лише стандартну бібліотеку Python 3.9+. Після запуску він перевіряє: розмітка збігається з колонками файлів, контрольні суми коректні, «пастки» їх не проходять, усі імена з `payroll.csv` і `customers.json` є у словниках. Змінили кількості або колонки: оновіть розмітку у скрипті й цей файл.
